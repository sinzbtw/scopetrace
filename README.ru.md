# ScopeTrace

[![CI](https://github.com/sinzbtw/scopetrace/actions/workflows/ci.yml/badge.svg)](https://github.com/sinzbtw/scopetrace/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Локальный статический анализ **scopes GitHub OAuth Apps** в JavaScript и TypeScript. Сопоставление объявленных прав с поддерживаемыми API-операциями: позиции в коде, обоснования и официальная документация.

[Лицензия MIT](LICENSE) · Node.js 22+ · Версия 0.1.0

## Зачем нужен ScopeTrace

Объявления OAuth-разрешений нередко переживают функции, которым они нужны. ScopeTrace даёт воспроизводимые основания для исследования широких и недостающих прав без загрузки исходников на сервер и без токена. Анализ не доказывает, что разрешение можно безопасно удалить.

Это независимый проект, не связанный с другими продуктами под названием ScopeTrace.

## Возможности

- AST-анализ JS/JSX/TS/TSX через TypeScript Compiler API.
- Импортированные конструкторы Octokit, алиасы, CommonJS-деструктуризация, REST-методы и литеральные request-маршруты.
- Глобальный fetch со статическими GitHub URL и HTTP-методами.
- Тринадцать версионированных правил, вложенность scopes, нормализация и документированные альтернативы.
- Файл/строка/столбец, стабильные ID, обоснование, уверенность и документация.
- Терминальные, JSON- и Markdown-отчёты; пороги для CI.
- Локальный обход с лимитами, исключением файлов секретов и пропуском ссылок/junctions.

## Ограничения анализа

Поддерживаются только **GitHub OAuth Apps**. Права GitHub Apps и fine-grained PAT относятся к другим моделям и не переводятся в scopes.

Разрешение значений ограничено поддерживаемыми внут­рифайловыми const-алиасами и литералами. Обёртки, межфайловые потоки, динамические шаблоны, GraphQL, собственные транспорты, другие HTTP-клиенты, помощники пагинации, default-импорты, фабрики конструкторов и экспортированные клиенты не поддерживаются. Некоторые неподдерживаемые формы вообще не распознаются. Динамические цели fetch отмечаются как кандидаты, которые могут обращаться к другому провайдеру.

Каждый обнаруженный вызов сравнивается с одним набором scopes. Анализ не отслеживает токены, не проверяет достижимость, содержимое ответов, выданные права, доступ пользователя, SSO и политики организаций. Распознаваемые собственные транспорты/base URL Octokit дают unknown. Видимость репозитория не угадывается.

Возможный избыток всегда имеет низкую уверенность. Перед сокращением прав проверьте исключения, unknown-вызовы и поведение приложения. Полнота обхода означает обработку выбранных файлов в пределах лимитов, а не исследование всего поведения приложения.

## Установка

Пакет **не опубликован в npm**. Соберите публичные исходники:

```sh
git clone https://github.com/sinzbtw/scopetrace.git
cd scopetrace
npm ci --ignore-scripts
npm run build
node dist/cli/main.js --help
```

Для CLI нужен Node.js 22+. Для проверок разработки — Node.js 22.13+ либо актуальная версия 24/26. При желании установите собранную копию как команду через `npm install --global . --ignore-scripts`. Это не означает публикацию в реестре npm.

## Быстрый старт

После установки собранной команды запустите в корне приложения:

```sh
scopetrace init
# Отредактируйте scopetrace.config.json: объявите scopes и выберите исходники.
scopetrace scan
scopetrace scan --format json --output report.json
scopetrace scan --format markdown --output report.md
scopetrace scan --fail-on high
```

Без глобальной установки замените `scopetrace` на `node /absolute/path/to/scopetrace/dist/cli/main.js`, оставаясь в корне приложения. На Windows используйте фактический абсолютный Windows-путь.

## Конфигурация

`init` создаёт новый `scopetrace.config.json` без перезаписи. Это только данные JSON:

```json
{
  "provider": "github-oauth",
  "declaredScopes": ["user:email", "repo", "workflow"],
  "include": ["src/**/*.{js,jsx,ts,tsx}"],
  "exclude": ["**/*.test.*", "**/*.spec.*"],
  "repositoryVisibility": "unknown",
  "limits": {
    "maxFiles": 2000,
    "maxFileBytes": 524288,
    "maxTotalBytes": 20971520,
    "maxEntries": 50000,
    "maxDepth": 32
  }
}
```

Неизвестные ключи/провайдеры, неправильные лимиты и шаблоны с выходом из каталога отклоняются. На всех платформах используйте относительные glob-шаблоны с прямыми слешами. Конфигурация — JSON внутри корня размером не более 64 КиБ. Неизвестные названия scopes дают unknown-находки без вывода значений.

Видимость: unknown (по умолчанию), public или private. Явное значение — ваше утверждение о **всех моделируемых чтениях репозиториев** в запуске. Для разной видимости используйте отдельные проверки. Публичное чтение не обосновывает scope; моделируемое приватное требует repo со средней уверенностью, поскольку видимость задана пользователем. Без утверждения получается unknown.

Без include/exclude выбираются все поддерживаемые расширения, кроме test/spec-файлов. Стартовая конфигурация ограничена src/. Зависимости, данные VCS, результаты сборки, файлы окружения и имена приватных ключей исключаются независимо от include.

## Команды

| Команда | Назначение |
| --- | --- |
| `scopetrace init` | Создать стартовую конфигурацию |
| `scopetrace scan` | Проверить текущий рабочий каталог |
| `scopetrace scan --config custom.json` | Другой JSON внутри корня |
| `scopetrace scan --format text\|json\|markdown` | Выбрать формат |
| `scopetrace scan --output report.json` | Создать новый файл отчёта |
| `scopetrace scan --fail-on high` | Блокировать достаточно уверенную нехватку прав |
| `scopetrace rules` | Правила, альтернативы, условия и источники |
| `scopetrace --help / --version` | Справка/версия |

Выходной файл не должен существовать; родительские каталоги должны существовать и не разрешаться через ссылки. JSON stdout содержит только отчёт, ошибки идут в stderr.

Код **0**: проверка завершена; **1**: недостаточность прав достигла порога важности со средней/высокой уверенностью; **2**: ошибка выполнения/конфигурации. Пороги: info, low, medium, high. Unknown и возможный избыток не вызывают код 1. Пустой/усечённый анализ явно отмечается incomplete/unknown и сам по себе не блокирует проверку.

## Реальные примеры

```ts
import { Octokit as GitHub } from '@octokit/rest';
const api = new GitHub({ auth: process.env.GITHUB_TOKEN });
api.rest.users.listEmailsForAuthenticatedUser(); // user:email либо более широкий user
api.request('DELETE /repos/{owner}/{repo}', {
  owner: 'example', repo: 'sample'
}); // delete_repo; одного repo недостаточно
fetch('https://api.github.com/repos/example/sample');
// public: без scope; private: repo; видимость не задана: unknown
```

Правила также охватывают запись email (user), подписку/отписку (user:follow), запись gist (gist), публичное чтение пользователей/gist и чтение содержимого репозитория. См. [правила](docs/rules.md). Распознавание не доказывает выполнение или успех операции.

После сборки запустите встроенный пример:

```sh
cd tests/fixtures/basic
node ../../../dist/cli/main.js scan --format json --fail-on high
```

Он возвращает **1**: объявлены user:email и workflow, но удаление репозитория требует delete_repo.

## Пример отчёта

```text
[insufficient/high/high] ST-<stable-hash> src/app.ts:4:1 DELETE /repos/{owner}/{repo}
  Deleting a repository requires delete_repo and repository administration access.
  Rule: gh.repo.delete
```

ID показан схематично: реальные значения зависят от позиции и идентичности операции. JSON schemaVersion — 1.0.0; поля analysis, operations и findings включают альтернативы, документацию и уверенность. [JSON Schema](schemas/report.schema.json). Markdown экспортирует те же находки для ревью.

Категории: observed, possibly_excessive, insufficient, unknown, not_applicable.

## CI/CD

[CI](.github/workflows/ci.yml) проверяет Windows/Linux на Node.js 22/24/26: типизацию, ESLint, unit/integration-тесты с покрытием, сборку и запуск/gate собранного CLI. Права ограничены чтением, Actions закреплены по SHA.

Для стороннего репозитория соберите эти исходники на проверенном **полном SHA коммита** и запустите CLI против своей копии. Скопируйте [пример CI](examples/github-actions.yml) и сохраните конфигурацию приложения. Пример закреплён на проверенном коммите реализации; меняйте SHA после ревью. Используются доступные исходники, а не неопубликованный пакет из реестра.

## Разработка и тесты

```sh
npm ci --ignore-scripts
npm run check
npm run smoke
npm audit --audit-level=moderate
```

Check запускает типизацию, линтер, тесты с покрытием и сборку. Проверяются алиасы, затенение имён, переопределения маршрутов, необычный синтаксис, приватность, вложенность scopes, отчёты, коды выхода, лимиты, порядок и ссылки. Пороги покрытия: 85% строк/инструкций/функций и 75% ветвей. Исключена только маленькая точка входа процесса. Ошибки разбора враждебных исходников дают unknown-уведомления.

## Безопасность и приватность

Сканирование не требует токена, не обращается к сети, не загружает модули/скрипты проекта и не меняет исходники. Отчёты содержат относительные имена файлов и шаблоны операций; фрагменты кода, тела запросов, произвольные сегменты URL, query-значения и заголовки исключены. Имена файлов и известные объявленные scopes остаются видимыми.

Ссылки/junctions пропускаются; проверяются реальные пути, идентичность обычных файлов и лимиты байтов. Это защита от статического недоверенного репозитория, а не локального процесса, одновременно подменяющего файловую систему. Не меняйте проверяемую копию во время анализа. Модель угроз и приватное сообщение об уязвимостях: [SECURITY.md](SECURITY.md).
